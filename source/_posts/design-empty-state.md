搜索无结果、购物车是空的、新用户刚注册还没有内容——这些"没有数据"的界面，在产品里可能只占 5% 的页面量，却承担了 **100% 的第一印象**。

而最常见的做法是留一片空白，或者显示一句「暂无数据」。

<!-- more -->

## 一、空状态至少分四种，不能一概而论

| 类型 | 场景 | 目标 |
| --- | --- | --- |
| **初次空态** | 新用户、新建的列表 | **引导行动**：告诉用户怎么开始 |
| **结果空态** | 搜索无结果、筛选无匹配 | **给出出路**：告诉用户怎么调整 |
| **错误空态** | 加载失败、无权限 | **解释原因 + 提供恢复** |
| **完成空态** | 待办清空、收件箱已读 | **正向反馈**：这是好事 |

{% note danger 用一句话应付所有类型是最大错误 %}
「暂无数据」对**初次空态**是灾难——用户不知道该干什么，很可能就此离开。

而对**完成空态**（待办全做完了），显示「暂无数据」又完全错了——这是个值得庆祝的时刻。
{% endnote %}

## 二、初次空态：要引导，不要陈述

```text
❌ 暂无文章

✅ 还没有写过文章
   [写第一篇 →]
   文章会出现在这里，支持 Markdown 与标签插件。
```

初次空态必须回答三件事：

{% timeline %}
{% event 这是什么 %}
说明这个区域将来会放什么（"文章会出现在这里"）。
{% endevent %}
{% event 我该怎么开始 %}
给一个明确的主按钮，动词开头（"写第一篇"而非"新建"）。
{% endevent %}
{% event 做了会怎样 %}
一句话打消顾虑（"支持 Markdown"）。可选，但对复杂产品很有用。
{% endevent %}
{% endtimeline %}

{% note tip 这是转化率最高的位置之一 %}
初次空态出现在用户**注意力最集中、且还没有形成使用习惯**的时刻。这里的引导按钮点击率通常远高于常态界面里的同类按钮。

不要浪费它。
{% endnote %}

## 三、结果空态：要给出路，不要只说没有

搜索「xyz」没有结果时：

```text
❌ 没有找到相关内容

✅ 没有找到与「xyz」相关的内容

   建议：
   · 检查拼写
   · 换个说法试试（比如「Hexo」）
   · [清除筛选条件]
```

{% fold 为什么要回显用户的输入 %}
回显「xyz」有两个作用：

1. **确认系统确实按你的输入搜了**（用户会怀疑是不是没生效）；
2. **让"没有结果"这个事实显得合理**——用户看到自己输的词，会自己判断是不是太偏了。

不回显时，用户的第一反应是"这个搜索是不是坏了"。
{% endfold %}

结果空态的核心动作是**降低重新尝试的成本**：提供清除筛选、给出相近词、列出热门内容。

## 四、错误空态：解释 + 恢复

```text
❌ 加载失败

✅ 内容没能加载出来
   网络连接似乎有问题。
   [重试]
```

错误空态必须包含：

1. **人话描述**（不是错误码）；
2. **可能的原因**（可选，但能显著降低焦虑）；
3. **恢复动作**（重试按钮，或者告诉用户该怎么处理）。

{% note warning 不要把技术细节抛给用户 %}
`Error: ECONNREFUSED 127.0.0.1:3000` 对用户毫无意义。技术上要记日志，界面上要说人话。

如果需要错误码供技术支持定位，放在**折叠区或复制按钮后面**，不要直接显示。
{% endnote %}

## 五、完成空态：值得设计的正向时刻

```text
✅ 全部完成 🎉
   你已经处理完所有待办。
   [查看已完成项]
```

这类空态是产品里少有的**正面时刻**，值得做得比其它页面更用心一点。但要注意克制——不要过度庆祝（满屏撒花动画），一个图标加一句肯定就够。

## 六、视觉上的三个共识

{% row %}
{% col %}
**一、要有视觉载体**

纯文字的空状态像"页面坏了"。至少配一个插画或图标，让它看起来是**设计过的页面**而不是**出错的页面**。
{% endcol %}
{% col %}
**二、不要占据全屏高度**

空状态应该出现在"内容本该出现的位置"，而不是撑满整个视口。前者是"这里将来有内容"，后者是"这个页面是空的"。
{% endcol %}
{% endrow %}

{% note info 三、保留周边结构 %}
如果列表有筛选栏、工具栏，空状态里**依然要显示它们**。用户可能在筛选栏里找到出路（比如切换条件），把它们藏起来等于堵死退路。
{% endnote %}

## 七、文案的写法

{% row %}
{% col %}
**要这样**

- 说"还没有"，而不是"没有"（暗示这是暂时的）
- 动词开头：「写第一篇」「上传文件」
- 具体：「没有 2026 年的订单」优于「无数据」
{% endcol %}
{% col %}
**不要这样**

- 「无」「空」「N/A」「-」
- 全大写或无标点
- 责怪用户：「你没有创建任何内容」
{% endcol %}
{% endrow %}

## 八、工程上的注意点

空状态和**加载中**是两种不同的状态，不要合并处理：

```js
// ❌ 用同一个分支
{ !list.length && <Empty /> }

// ✅ 区分
if (loading) return <Skeleton />;
if (error)   return <ErrorState onRetry={reload} />;
if (!list.length) return <Empty onCreate={...} />;
```

{% note danger 最常见的 bug %}
`!list.length` 在**数据还没返回**时也是 true，于是页面先闪一下空状态、再显示内容。用户看到的是"短暂的错误信息"。

必须先判 `loading`。这个 bug 在异步渲染里出现频率极高。
{% endnote %}

## 九、纯静态站点怎么办

本站是 Hexo 生成的静态站，没有后端动态数据，但依然有空状态场景：搜索无结果、分类下暂时没有文章、评论数为 0。

静态站的空态处理要点：

1. **构建期就能确定是否为空**（分类页是否有文章是已知的），可以直接生成不同的 HTML，不需要 JS 判断；
2. **搜索空态**是唯一需要运行期处理的，静态搜索（如本地索引）要在回调里区分"未开始/无结果"；
3. **评论为空**时给出引导文案，而不是留白。
