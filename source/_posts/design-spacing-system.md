同样一个卡片，改一改里面的间距，观感能从"随手做的"变成"设计过的"。而 spacing 之所以难调，是因为大多数人**凭感觉写数值**：这里 15px，那里 18px，凑近看都说不出哪里不对。

<!-- more -->

## 一、为什么要用网格系统

```css
/* ❌ 凭感觉 */
.card { padding: 15px; margin-bottom: 18px; gap: 11px; }

/* ✅ 有系统 */
.card { padding: var(--sp-4); margin-bottom: var(--sp-6); gap: var(--sp-3); }
```

凭感觉写的问题不是单个数值不好看，而是：

1. **无法对齐**：不同组件的间距互不相同，页面看起来"没对齐"；
2. **无法共振**：相邻区块的间距差异太小（16 vs 18），既不像"相同"也不像"不同"，处于最难受的模糊地带；
3. **无法维护**：要整体调大间距时，你得一个个改。

## 二、8pt 网格是什么，以及它的取舍

8pt 网格就是**所有间距都是 8 的倍数**：

```css
--sp-1: 4px;    /* 半档，用于图标与文字的贴合 */
--sp-2: 8px;
--sp-3: 12px;   /* 半档（8 + 4） */
--sp-4: 16px;
--sp-6: 24px;
--sp-8: 32px;
--sp-12: 48px;
--sp-16: 64px;
```

{% note info 为什么是 8 %}
8 能被 2、4 整除，容易二分；同时与常见的 16px 默认字号、以及多数屏幕的像素密度契合。

4pt 网格（更细）适合需要精密排版的界面；8pt 是**通用场景的最佳平衡**。
{% endnote %}

### 半档要不要留

`4px` 和 `12px` 不是 8 的倍数，但实践中非常必要：

- `4px`：图标与相邻文字的最小呼吸空间；
- `12px`：8 太大、16 太小时的唯一选择（按钮内边距、标签间距）。

{% note tip 建议 %}
**主档用 8 的倍数，另开两个半档（4 / 12）作为补充。** 不要开更多——半档一多，网格就失去意义了。
{% endnote %}

## 三、该定几档

太多等于没有。经验值是 **7~8 档**，覆盖从"紧贴"到"区块分隔"：

| 变量 | 值 | 典型用途 |
| --- | --- | --- |
| `--sp-1` | 4px | 图标与文字、标签内部 |
| `--sp-2` | 8px | 紧凑列表项、表单元素间 |
| `--sp-3` | 12px | 按钮内边距、卡片内小间距 |
| `--sp-4` | 16px | **卡片内边距**（最常用） |
| `--sp-6` | 24px | 卡片之间、段落区块间 |
| `--sp-8` | 32px | 区块之间 |
| `--sp-12` | 48px | 页面级分隔、章节间 |
| `--sp-16` | 64px | 大区块、首屏留白 |

{% note danger 相邻档位的比值要拉得开 %}
8 → 12 → 16 → 24 → 32：相邻档至少差 **1.5 倍**。这样"用哪一档"是明确的选择，而不是纠结 16 还是 18。

这也是凭感觉写数值时最容易犯的错：**16 和 18 同时存在**，既浪费档位又制造模糊。
{% endnote %}

## 四、间距的层级规律

一个反直觉但极其重要的原则：

> **相关性越强的元素，间距越小；相关性越弱，间距越大。**

```
标题
  ← 8px（强相关：标题属于它下面的内容）
正文段落
  ← 24px（弱相关：这是另一个段落）
另一个段落
  ← 48px（更弱：这是下一个章节）
```

{% fold 这条规律能解决 80% 的间距问题 %}
看到"两个元素之间该留多少"，先问：**它们是一伙的吗？**

- 标题和它的正文 → 一伙 → 小间距（8px）
- 两个并列的卡片 → 同级但独立 → 中间距（24px）
- 文章区和侧栏 → 不同区域 → 大间距（32~48px）

凭这个规则定出来的间距，即使不精确符合网格，观感也不会差。
{% endfold %}

## 五、外边距该由谁负责：单向原则

这是团队协作时最容易乱的地方。两个人各写一个组件，都设了 `margin-bottom`，叠在一起就变成双倍间距。

**约定：只用一个方向的外边距**（通常是 `margin-bottom`），且**由"前面的元素"负责与后面元素的间距**。

```css
/* ✅ 统一往下推 */
.post + .post { margin-top: var(--sp-6); }

/* ❌ 混用会造成折叠与双倍 */
.post { margin-bottom: var(--sp-6); margin-top: var(--sp-4); }
```

{% note warning 更现代的做法：用 gap 代替 margin %}
Flex/Grid 容器用 `gap` 声明子项间距，**容器负责，子项完全不管**：

```css
.post-list { display: flex; flex-direction: column; gap: var(--sp-6); }
```

这样彻底消除了"谁负责外边距"的问题——没人负责，容器负责。能用 `gap` 的场景优先用它。
{% endnote %}

## 六、内外边距的比例感

同一元素的 padding 和它内部的 gap，通常满足：

```
外边距 > 内边距 > 内部间距
```

一个卡片：`margin-bottom: 24px` → `padding: 16px` → 内部元素间 `gap: 8px`。

{% note info 违反这个规律会怎样 %}
如果内边距大于外边距（padding 24px、卡片间距 16px），卡片之间会显得**挤**，而卡片内部显得**空**——典型的"没设计过"的观感。
{% endnote %}

## 七、一个立刻能用的自检方法

{% timeline %}
{% event 第一步 %}
把页面上所有间距值列出来（DevTools 里逐个量，或者全局搜索 `padding` / `margin` / `gap`）。
{% endevent %}
{% event 第二步 %}
看是否出现了"相差 1~3px 的近似值"（16 和 18、24 和 26）。有就合并——**近似值是模糊感的来源**。
{% endevent %}
{% event 第三步 %}
检查是否都落在网格上。不在网格上的值，问一句"它为什么特殊"。
{% endevent %}
{% event 第四步 %}
把页面缩小到 30% 看整体。间距有问题时会表现为"有的地方挤成一团、有的地方空得突兀"。
{% endevent %}
{% event 第五步 %}
移动端单独查一遍：桌面合适的间距在手机上往往过大，通常要整体降一档（如 `--sp-6` → `--sp-4`）。
{% endevent %}
{% endtimeline %}

## 八、移动端的间距收缩

桌面 24px 的区块间距，在 390px 宽的手机上占 6% 的屏幕高度，显得过大。常见做法是**按档位整体降一档**：

```css
.section { padding-block: var(--sp-12); }

html[data-tier="mobile"] .section {
  padding-block: var(--sp-8);
}
```

{% note tip 只降大档，不降小档 %}
`--sp-2`（8px）这类小间距在手机上不用改——它本来就小。需要收缩的是 `--sp-8` 以上的区块级间距。

全部等比缩小会让界面变得局促，只缩大的那几档才对。
{% endnote %}
