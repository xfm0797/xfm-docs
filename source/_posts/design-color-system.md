设计师给了你一个品牌色 `#4F6BED`，然后呢？

界面里需要的远不止一个颜色：正文、次文本、边框、背景、悬浮态、成功、警告、错误……**只靠一个品牌色是拼不出界面的**，必须有方法把它展开成一套系统。

<!-- more -->

## 一、三层结构

```text
第一层  原始色阶      blue-50 … blue-900   （纯色值，无语义）
   ↓
第二层  语义色        --c-primary  --c-text  --c-danger  --c-surface
   ↓
第三层  组件          .btn-primary { background: var(--c-primary) }
```

{% note danger 组件永远不准引用第一层 %}
这条规则和"不准写死数值"是同一件事。组件引用 `--blue-600` 的后果是：**换品牌色时要改所有组件**；而引用 `--c-primary`，只需要改一处映射。

深色模式同理——组件引语义色，换肤时只改语义层的指向。
{% endnote %}

## 二、从品牌色生成色阶

手工挑 9 个色值既费时又不均匀。常见做法有两种：

### 方法一：HSL 明度阶梯

保持色相与饱和度，只改明度：

```css
:root {
  --brand-h: 228;
  --brand-s: 80%;
  --blue-50:  hsl(var(--brand-h) var(--brand-s) 96%);
  --blue-100: hsl(var(--brand-h) var(--brand-s) 90%);
  --blue-200: hsl(var(--brand-h) var(--brand-s) 80%);
  --blue-500: hsl(var(--brand-h) var(--brand-s) 55%);  /* 主色 */
  --blue-700: hsl(var(--brand-h) var(--brand-s) 42%);  /* 悬浮态 */
  --blue-900: hsl(var(--brand-h) var(--brand-s) 24%);
}
```

{% fold 为什么纯 HSL 明度阶梯不够好 %}
HSL 的 `L` 是**数学明度**而非**感知明度**。同样是 `L: 50%`，黄色看起来比蓝色亮得多——因为人眼对不同波长的敏感度不同。

结果就是：同一套 `L` 值生成的不同色相，视觉深浅不一致。黄色系偏亮、蓝色系偏暗。

进阶方案用 OKLCH（感知均匀色彩空间），同样的 `L` 值在不同色相下感知亮度一致：

```css
--blue-500: oklch(55% 0.18 264);
--green-500: oklch(55% 0.15 145);   /* 视觉上与上面一样亮 */
```
{% endfold %}

### 方法二：叠加法（更实用）

不用算色彩空间，直接在品牌色上叠加白/黑：

```css
:root {
  --brand: #4F6BED;
  --brand-rgb: 79 107 237;   /* 关键：存 RGB 三元组 */
}

/* 用 color-mix 或从 RGB 派生透明度 */
.btn-primary {
  background: var(--brand);
}
.btn-primary:hover {
  background: rgb(var(--brand-rgb) / .88);
}
.btn-ghost {
  background: rgb(var(--brand-rgb) / .08);   /* 浅底 */
  color: var(--brand);
}
```

{% note tip 为什么要把品牌色存成 RGB 三元组 %}
因为 CSS 里**没有"给一个颜色加深/减淡"的函数**（`color-mix` 支持度还在普及中），最通用的做法是手动存一份 `79 107 237`，然后用 `rgb(79 107 237 / .5)` 派生任意透明度。

这是目前兼容性最好、也最灵活的做法。本站主题的品牌色就是这么存的。
{% endnote %}

## 三、语义色不等于色阶

色阶是"有哪些颜色"，语义色是"这个位置该用什么颜色"。两者必须分开：

```css
:root {
  /* 语义层：指向色阶 */
  --c-primary:      var(--blue-500);
  --c-primary-weak: var(--blue-50);
  --c-text:         var(--gray-900);
  --c-text-2:       var(--gray-600);
  --c-text-3:       var(--gray-400);
  --c-border:       var(--gray-200);
  --c-surface:      #fff;
  --c-surface-2:    var(--gray-50);
}
```

### 文本为什么要分三级

| 变量 | 用途 | 对比度目标 |
| --- | --- | --- |
| `--c-text` | 正文、标题 | ≥ 7:1（AAA 级正文） |
| `--c-text-2` | 次要说明、元信息 | ≥ 4.5:1（AA 级） |
| `--c-text-3` | 占位符、禁用态 | ≥ 3:1（非文本必需时可放宽） |

{% note warning 灰色不是随便挑的 %}
很多人直接写 `#999`、`#666`。问题是：这些灰色**没有色相倾向**，放在有品牌色的界面里会显得脏。

正确做法是让中性色带一点品牌色相（冷色品牌配冷灰，暖色品牌配暖灰），整体才协调。

```css
/* 冷灰：轻微偏向蓝色的灰 */
--gray-500: hsl(228 12% 46%);
```
{% endnote %}

## 四、深色模式不能靠"调暗"

这是最普遍的误解。深色模式**不是把浅色值调暗**，因为：

1. **纯黑背景 + 纯白文字对比过强**，长时间阅读刺眼（光晕效应）；
2. **饱和度在深底上感知会变高**，浅色下合适的饱和色，放到深底上会"跳出来"；
3. **阴影在深色下无效**，需要用边框和亮度差替代层级表达。

```css
:root {
  --c-surface: #ffffff;
  --c-text: #1b1f26;
  --c-border: rgba(17, 24, 39, .08);
  --c-primary: #4F6BED;
}

html[data-scheme="dark"] {
  /* 不是 #000，是深灰 */
  --c-surface: #161b23;
  /* 不是 #fff，是米白，降低刺眼感 */
  --c-text: #e6e9ef;
  /* 深色下边框改成"提亮"，因为阴影失效了 */
  --c-border: rgba(255, 255, 255, .09);
  /* 关键：深色下主色要提亮、降饱和 */
  --c-primary: #7c92f5;
}
```

{% note info 深色下的主色要改，不只是背景 %}
浅色界面里 `#4F6BED` 的蓝，放到 `#161b23` 上会显得暗沉、点击欲望弱。深色模式的品牌色应该是**更亮、饱和度略低**的版本（`#7c92f5`）。

这就是为什么深色模式必须逐个语义变量重新调，而不能只改背景和文字。
{% endnote %}

## 五、对比度怎么算才靠谱

WCAG 的对比度公式不是简单的"亮度差"，它基于**相对亮度**：

```text
对比度 = (L1 + 0.05) / (L2 + 0.05)
```

其中 L 是相对亮度（0~1），计算时要对每个通道做伽马校正。

{% fold 手算太麻烦，用工具 %}
- 浏览器 DevTools 的颜色拾取器会直接显示对比度比值；
- 在线工具：WebAIM Contrast Checker；
- 命令行：`npx polished` 之类工具可批量计算。

**要测的是实际渲染出来的颜色**，不是你写的变量值——因为透明度叠加后的实际颜色和你写的不一样。
{% endfold %}

### 常见达标线

| 内容类型 | AA | AAA |
| --- | --- | --- |
| 正文文本（< 18pt） | 4.5:1 | 7:1 |
| 大文本（≥ 18pt 或 ≥ 14pt 粗体） | 3:1 | 4.5:1 |
| 界面组件、图形边界 | 3:1 | — |

{% note danger 最容易不达标的地方 %}
1. **占位符文字**（常写成 `#ccc`）
2. **禁用态**（常被压得太淡，但禁用态也需可辨认）
3. **品牌色上的白字**（品牌色往往不够深，白字对比度不足 4.5:1）
4. **链接色**（为了区分于正文常被调得很浅）

第 3 点尤其常见：**一个鲜亮的品牌蓝配白字，对比度常常只有 3.x:1**。解决办法是把按钮的主色改用色阶里更深的一档（如 blue-600 而非 blue-500）。
{% endnote %}

## 六、功能色不能只用颜色区分

```css
--c-success: #2f9e5f;
--c-warning: #d9822b;
--c-danger:  #d64545;
--c-info:    #4F6BED;
```

{% note warning 色盲友好性 %}
约 8% 的男性有不同程度的色觉障碍，红绿色盲最常见。**只用颜色区分成功/失败是不够的**，必须同时提供：

- 图标（✓ / ! / ×）
- 或文字标签

这是"不要仅靠颜色传达信息"这条无障碍原则的直接落地。
{% endnote %}

## 七、落地清单

{% timeline %}
{% event 一 %}
建立 9~10 级色阶（品牌色 + 中性灰即可，功能色可以只留主色）。
{% endevent %}
{% event 二 %}
定义语义层，让所有组件只引语义变量。
{% endevent %}
{% event 三 %}
逐个语义变量设计深色值，**不要批量调暗**。
{% endevent %}
{% event 四 %}
用工具测所有文本/背景组合的对比度，重点查占位符和白字按钮。
{% endevent %}
{% event 五 %}
检查功能色是否都有非颜色标识（图标或文字）。
{% endevent %}
{% endtimeline %}
