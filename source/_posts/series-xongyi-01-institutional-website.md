做完博客主题 `hexo-theme-xfm` 之后，我接到了一个完全不同性质的需求：**给机构做官网**——企业、政务、学校。做完才发现，这两类站点看着都是「一堆网页」，实际是两种物种。

这个系列记录 `hexo-theme-xongyi` 从零到落地的全过程。它比博客主题更短、更简单，但**产品决策的密度更高**——因为它的用户不是开发者，是需要自己改文案的客户。

<!-- more -->

## 一、机构官网和个人博客，差在哪

| 维度 | 个人博客 | 机构官网 |
| --- | --- | --- |
| 首页 | 时间线（最新文章） | **门面**（横幅 + 业务 + 案例 + 联系） |
| 内容类型 | 统一（文章） | 多样（产品 / 新闻 / 团队 / 案例） |
| 更新频率 | 高、持续 | 低、突发（发一条新闻、上一个产品） |
| 目标 | 被阅读 | **被联系**（咨询、到访、报名） |
| 改文案的人 | 作者本人 | **不懂代码的行政 / 办公室人员** |

最后一条是整个主题的**设计原点**：

{% note tip 一句话定位 %}
客户要能「自己改文案」，所以**所有内容必须是配置项，而不是模板里的硬编码文字**。
{% endnote %}

这直接决定了后面的所有取舍：为什么有 60+ 项配置、为什么首页是数组、为什么三套预设只能换配色。

## 二、三类客户要的不是一回事

我按客户类型拆了一遍诉求，发现它们对「好看」的定义完全不同：

| 客户 | 气质 | 首页重点 | 特殊要求 |
| --- | --- | --- | --- |
| **企业** | 商务、可信 | 核心业务 + 产品案例 + 数据 | 留资转化入口、立即咨询按钮 |
| **政务** | 严肃、权威 | 信息公开 + 快捷入口 + 通知公告 | 信息层级清晰、字体更重、无障碍 |
| **教育** | 亲和、学术 | 招生/课程 + 师资 + 校园风采 | 图文并茂、资讯更新频繁 |

于是有了三套**预设布局**：`enterprise`（商务蓝）/ `government`（政务红）/ `education`（学院青）。注意它们只是「气质预设」——**布局结构完全一致，只换配色和字重**，第二篇会展开。

{% note warning 一个反直觉的结论 %}
很多甲方会要求「我们不一样，要定制设计」。但真正让他们满意的往往不是独特布局，而是**配色对、文案准、手机上好看**。把 80% 的差异收敛成预设，比做三套模板划算得多。
{% endnote %}

## 三、为什么还是 Hexo

机构官网的技术选型，通常在这几条路里选：

| 方案 | 优点 | 为什么不选 |
| --- | --- | --- |
| WordPress / CMS | 客户能后台编辑 | 要服务器、要运维、有安全更新负担 |
| SPA（Vue / React） | 交互自由 | 官网内容少、SEO 要求高，SPA 是负优化 |
| **静态站（Hexo）** | 免费托管、零运维、天生 SEO | 客户不能直接后台编辑 |

选静态站的理由很现实：**机构官网的内容更新频率极低（一个月几条新闻），但托管成本要永远为零**。为了一年 12 次更新去养一台服务器，不划算。

代价是客户不能后台编辑。我的补偿方案是：

1. **配置驱动**：所有文案都在 `_config.yml` 里，改完重新部署即可；
2. **文章即新闻**：发新闻就是新建一个 Markdown 文件；
3. **一键部署**：推到 GitHub 就自动上线，不需要懂命令行。

## 四、仓库形态的两次取舍

这是这个项目里我最想讲的产品决策。

### 第一版：完整站点 + 内嵌主题

```
hexo-theme-xongyi/
├─ _config.yml          # 站点配置
├─ source/              # 示例内容
└─ themes/xongyi/       # 主题本体
```

**理由**：各大平台都支持「导入仓库即部署」。客户把仓库连到 Netlify / Vercel，什么都不用配就有一个能看的官网——**转化率极高**。

### 终版：官方主题仓库（根目录即主题本体）

```
hexo-theme-xongyi/
├─ _config.yml          # 主题配置
├─ layout/  source/  scripts/  languages/
└─ examples/            # 预设示例配置
```

**改回去的理由**：作为「主题」被使用时，第一版形态会让 `git clone` 得到一层嵌套站点，装不进 `themes/` 目录。而官方主题仓库形态可以：

```bash
git clone https://github.com/xfm0797/hexo-theme-xongyi.git themes/hexo-theme-xongyi
```

{% note info 两个需求怎么兼得 %}
最终方案是**拆成两个仓库**：
- `hexo-theme-xongyi` —— 纯主题（本系列的主角）
- `hexo-theme-xongyi-demo` —— 完整演示站（含示例内容 + 五大平台部署配置）

想「导入即部署」的用 demo 仓库，想集成到自己站点的用主题仓库。**不要试图用一个仓库满足两种用法。**
{% endnote %}

## 五、给自己划的四条硬约束

1. **零框架依赖**：原生 JS + 单个 CSS 文件（610 行），不引 jQuery / Tailwind；
2. **改文案不动代码**：60+ 项配置覆盖全部可见文字；
3. **预设只换皮**：`preset` 只影响 CSS 变量，不改结构；
4. **Node ≥ 18**：兼容主流构建平台。
