一个项目里出现 13px、14px、15px、16px、17px 五种字号，通常不是设计决策，而是**五次临时调整的产物**。

等到要做响应式、要适配深色模式、要给某个页面单独放大字号时，这套"自然生长"出来的字号就成了灾难——你不知道哪个该跟着变，哪个是特例。

<!-- more -->

## 一、等差序列为什么必然失败

```
12, 13, 14, 15, 16, 17, 18 …
```

等差序列的问题：**相邻两级的差异在视觉上不一致**。

12px 到 13px 是 8.3% 的变化，肉眼几乎看不出来；16px 到 17px 只有 6.3%，更看不出来。结果就是——**你有一半的档位白设了**，因为它们看起来是同一个大小。

而等比序列（模数音阶）的每一级差异都是**同一个百分比**，感知上均匀：

```
12 × 1.2 = 14.4 → 14
14 × 1.2 = 16.8 → 17
17 × 1.2 = 20.4 → 20
```

## 二、常用比例怎么选

| 比例 | 名称 | 观感 | 适用 |
| --- | --- | --- | --- |
| 1.125 | Major Second | 变化细腻，层级偏弱 | 文档、长文阅读 |
| 1.200 | Minor Third | 均衡，最常用 | **博客、通用站点** |
| 1.250 | Major Third | 对比明显 | 营销页、着陆页 |
| 1.414 | Augmented Fourth | 戏剧性强 | 海报、大标题展示 |
| 1.618 | 黄金比 | 跳跃剧烈 | 慎用，档位间空隙太大 |

{% note tip 本站的选择 %}
博客/文档类内容以**阅读**为核心，但如果比例太小，标题和正文又拉不开层级。1.2 ~ 1.25 之间是这类站点的最佳区间。

需要强烈视觉冲击的首页 Hero 区，可以跳出阶梯单独设一个"展示级"字号（比如 3rem），它不属于正文体系。
{% endnote %}

## 三、一套可直接用的阶梯

以 16px 为正文基准、比例 1.2：

```css
:root {
  --fs-xs:  0.75rem;   /* 12px  辅助说明、角标 */
  --fs-sm:  0.875rem;  /* 14px  次要信息、元信息 */
  --fs-base: 1rem;     /* 16px  正文 */
  --fs-md:  1.125rem;  /* 18px  小标题、引言 */
  --fs-lg:  1.375rem;  /* 22px  h3 */
  --fs-xl:  1.75rem;   /* 28px  h2 */
  --fs-2xl: 2.25rem;   /* 36px  h1 */
  --fs-3xl: 3rem;      /* 48px  展示级 */
}
```

{% note danger 规则：正文里不准出现裸数值 %}
定好阶梯后，所有字号都从变量取。**任何一处 `font-size: 15px` 都是技术债**——它会在某次整体调整时成为漏网之鱼。

真有特殊情况，也应该新增一个语义变量并注明用途，而不是就地写数字。
{% endnote %}

## 四、行高与字号是反比关系

这是最常被忽略的一条：**字号越大，行高应该越小**。

```css
h1 { font-size: 2.25rem; line-height: 1.2; }   /* 大标题紧凑 */
p  { font-size: 1rem;    line-height: 1.75; }  /* 正文宽松 */
```

原因：一行文字的物理长度越长，眼睛从行尾回到下一行行首越容易串行，需要**更大的行间距**来分隔。大标题通常只有一两行，不需要那么大的行距；正文长段落则需要。

{% row %}
{% col %}
**正文（中文）**：`1.7` ~ `1.8`

中文字符密度高、没有西文的下伸部，行高要略大于西文推荐值（1.5~1.6）。
{% endcol %}
{% col %}
**标题**：`1.2` ~ `1.35`

超过 1.4 会让标题看起来松散，失去"标题感"。
{% endcol %}
{% endrow %}

## 五、中文场景的三个特殊处理

### 一、不要用 `font-weight: 400` 做全站默认

中文没有真正的字重梯度（很多中文字体只有一个字重），浏览器会**合成伪粗体**——把笔画描粗，效果发虚。

```css
/* 中文标题优先用字重，但不要依赖 500/600 的细微差异 */
h1, h2 { font-weight: 600; }
strong { font-weight: 600; }   /* 而不是 700 */
```

### 二、行内代码与中英混排

```css
code {
  font-family: ui-monospace, "Cascadia Code", Consolas, monospace;
  /* 中文内容里行内代码要略微缩小，否则视觉上"顶"出来 */
  font-size: .9em;
}
```

中英混排时，**在中英文之间加一个空格**是通用规范（排版上的"盘古之白"），观感差异非常明显。

### 三、标点挤压与避头尾

```css
.prose {
  text-spacing-trim: space-first;   /* 处理行首标点 */
}
```

{% note warning 兼容性 %}
`text-spacing-trim` 支持度有限。更稳妥的做法是用 `text-wrap: pretty`（避免末行孤字）配合合理的段落宽度，这两个属性的优先级也高于标点挤压。
{% endnote %}

## 六、测量行长比调节字号更重要

很多人觉得"字号不合适"，其实是**行长不合适**。

一行的最佳长度是 **40~75 个字符**（西文）或 **30~45 个汉字**。超过这个范围，眼睛扫读效率急剧下降。

```css
.prose { max-width: 68ch; }   /* ch = 字符 0 的宽度，接近西文平均字宽 */
```

{% fold 中文用什么单位 %}
`ch` 单位基于西文数字 0 的宽度，一个汉字约等于 2ch。所以中文正文容器：

```css
.prose { max-width: 40em; }  /* 约 40 个汉字宽 */
```

或者更直接：`max-width: 720px` 配 16px 字号，实测约 45 个汉字——这是个经验上很舒服的值。
{% endfold %}

## 七、落地检查清单

{% timeline %}
{% event 一 %}
列出项目里出现过的所有 `font-size` 数值。如果超过 8 种，说明阶梯没建立起来。
{% endevent %}
{% event 二 %}
检查是否成等比。相邻档位的比值应该在 1.15~1.3 之间，且基本一致。
{% endevent %}
{% event 三 %}
把每个数值替换成语义变量（`--fs-sm` 而非 `--fs-14`——**用用途命名，不用数值命名**）。
{% endevent %}
{% event 四 %}
逐个检查行高，确认大字号配小行高。
{% endevent %}
{% event 五 %}
测一次行长：把一段正文放到最宽的容器里，数一数一行多少字。
{% endevent %}
{% endtimeline %}
